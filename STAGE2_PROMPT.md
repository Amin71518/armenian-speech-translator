- Windows, Python 3.13.5, Poetry, Intel Core i5-13420H, 16 ГБ RAM, без CUDA.
  Весь Python-проект, окружение и локальные артефакты — в SpeechRecognition.
- Используй существующие FastConformer INT8 и NLLB-200 distilled 600M greedy,
  загружая их один раз. Сохрани работающий WAV pipeline, интерфейсы и тесты.
  ASR пока принимает путь WAV, а не массив: предложи минимальный обоснованный способ
  передачи live-сегмента, не выдумывай уже готовый интерфейс.
- Не возвращай Whisper, Marian и M2M100 без технического обоснования.
  Не добавляй скрытых fallback-механизмов, ненужных абстракций или переписывания проекта.
- Пока не реализуй System Audio, Speaker Diarization, GUI, веб-серверы и базы данных.
  Не коммить веса, аудио и секреты; сохраняй реальные полные AI-сессии без редактирования.
  Кратко сообщай пользователю, что делаешь и как. Не выдавай WAV-метрики за live-тест.

## Подэтапы

**2.1 Microphone Capture — первая и единственная задача начальной реализации.**
Рассмотри sounddevice и проверь совместимость с Windows/Python 3.13.5 до выбора.
Перечисление/выбор устройства, непрерывный захват, фактический формат/частота/каналы,
счётчики ошибок/потерь и завершение по Ctrl+C. **Не подключай VAD и модели.**
Проверь захват на реальном устройстве и освобождение ресурсов; если доступа нет,
сообщи ограничение и дай конкретную команду ручной проверки. Не называй шаг проверенным
на устройстве по результатам одних mock-тестов.

**2.2 VAD + Segmentation.** Рассмотри Silero VAD, отдельно проверь совместимость и
CPU-стоимость. Определи буфер, pre-roll, пороги речи/тишины, trailing silence,
максимальную длительность и обработку длинной речи/финального остатка. Учитывай
требования VAD, текущего ASR и лимит NLLB. Сохрани временные метки реального аудио.

**2.3 Producer–Consumer Pipeline.** Предварительная схема:
Microphone Capture → VAD → Audio Buffer → Bounded Queue → Inference Worker → Terminal Output.
Раздели захват и инференс: callback не должен ждать моделей. Используй ограниченную
очередь готовых сегментов и явную согласованную политику переполнения с наблюдаемыми
счётчиками. Переиспользуй модели и терминальный вывод, для микрофона метка `Me`.
Определи передачу ошибок и завершение worker/очереди по Ctrl+C без зависаний.

**2.4 Live Latency Testing.** Измеряй monotonic timestamp фактического последнего
речевого сэмпла, решение VAD, ожидание очереди, ASR, перевод и завершение вывода.
E2E = вывод минус реальное окончание речи; включай VAD hangover и ожидание очереди.
Не начинай таймер после решения VAD. Проверь speech-end по независимо размеченной
записи; опиши точность временных меток. На согласованном наборе покажи среднее,
перцентили, максимум и все превышения ≤5 с; низкого среднего/RTF недостаточно.
Проверь длительный захват, медленный consumer, переполнение и Ctrl+C.

Для каждого шага: Plan → Implement → Test → Measure; решение о коммите согласуй
с пользователем. Запускай
`poetry run python -m pytest -q -p no:cacheprovider --basetemp .cache/pytest`,
`poetry run ruff check .`
и подходящие реальные проверки. После интеграции повтори WAV-регрессию:
`poetry run armenian-speech --manifest data/local/fleurs/manifest.jsonl --offline --report reports/stage2_wav_regression.json`.
Документируй факты и ограничения, не обещай задержку или качество без измерений.
